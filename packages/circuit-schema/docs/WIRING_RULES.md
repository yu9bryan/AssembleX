# 麵包板接線規範（AssembleX Wiring Rules v1）

這份規範定義「導線怎麼接」。AI 只負責**設計**（用哪些元件、插在哪些孔、哪些腳要相連）；
**接線一律由演算法依本規範產生**（`src/autowire.ts` 的 `autoWire()`），產生後由驗證器檢查，
不靠模型或人工逐條確認。規範只依賴孔位資料（導通群組、電源軌、座標），適用任何尺寸的麵包板。

---

## 0. 名詞

| 名詞 | 意思 |
|---|---|
| 導通群組（tie group） | 板子內部本來就相通的一組孔。主區每一欄的 A–E 一組、F–J 一組；電源軌依分段各一組。 |
| 端點（terminal） | 一個網路要接到的地方：一個導通群組（元件腳插在裡面），或開發板的一隻腳（板子不插麵包板時）。 |
| 電源軌 | `kind: "rail"` 的孔。名稱以 `+` 結尾的是電源軌、`-` 結尾的是地線軌。可能分段（830 孔板在 25/26 之間斷開）。 |
| 空孔 | 沒有元件腳、沒有線端，而且**沒有被任何元件本體蓋住**的孔。 |

## 1. 硬性規則（違反就是錯，驗證器會擋下）

- **R1 已相通不接線**：同一個網路裡，插在同一個導通群組的腳本來就相通，不另外拉線。
- **R2 只插自己的群組**：一條線的端點只能插在「它所屬網路的導通群組」裡的空孔，或該網路的電源軌、開發板腳位。絕不能插進別的網路的群組（會短路）。
- **R3 一孔一物**：一個孔只能有一隻元件腳或一個線端（`detectHoleConflicts`）。
- **R4 不插在本體底下**：線端不能插在元件本體投影範圍內的孔（`blockedHoleErrors`）。
- **R5 連通等於設計**：接完線後，實體連通（板內導通＋導線＋插孔）必須和 `logical.nets` 完全一致——不能少接、不能多接、電源不能碰地（`runElectricalChecks`）。
- **R6 實體不碰撞**：佈線後兩條線的管徑不能互相穿過（`findWireCollisions`）。

## 2. 電源與地

- **P1 走軌道**：`role` 為 `power` 的網路接到 `+` 軌、`ground` 接到 `-` 軌。每個端點就近接到軌上 x 最接近的空孔。
- **P2 選哪一條軌**：同極性有多條軌時（830 孔板上下各一組），選靠近開發板的那條（排線短）；搜尋時也會試靠近元件群的那條。
- **P3 分段要橋接**：軌道分段時，只要一個網路用到兩段以上，就在相鄰兩段的交界處各取最靠近交界的空孔補一條橋接線。
- **P4 開發板的電源／地腳**：接到軌上的位置會影響排線會不會和訊號線交叉，演算法在整條軌上取樣挑最好的位置（跨段自動補 P3 的橋接線）。
- **P5 沒有軌道的板子**（例如 170 孔迷你板）：電源與地照訊號網路（第 3 節）處理。
- **P6 3.3V 板**：電源網路接開發板的 3V3 腳（由開發板設定決定），規則不變。

## 3. 訊號

- **S1 樹狀串接**：一個網路的所有端點用最小生成樹相連（曼哈頓距離），有開發板腳位時以它為根。
- **S2 選孔**：從群組裡選最靠近另一端的空孔（線最短）；搜尋時也試「離元件本體最遠」的孔。

## 4. 顏色

| 網路 | 顏色 |
|---|---|
| 電源 | `#d6484d` 紅 |
| 地 | `#1f2937` 深灰 |
| 訊號 | 依網路順序從固定色盤分配，不重複：綠 `#4ade80`、藍 `#2f6fd0`、黃 `#f5a524`、紫 `#a78bfa`、橘、青、粉… |

同一個網路的所有線同色；網路清單、3D、韌體面板的色條都讀同一個顏色。

## 5. 品質目標與選擇

演算法會產生多組候選（固定策略＋時間預算內的隨機搜尋，固定種子可重現），依序比較：

1. 規則問題數（R1–R6）最少，必須是 0 才算成功；
2. 實體碰撞 0；
3. 俯視交叉最少（目標 0；不影響電路正確，但影響好不好看、好不好照著插）；
4. 總線長最短。

## 5.1 元件位置與腳位最佳化

- **L1 位置最佳化（模擬退火）**：不改電路，只把元件左右平移 1–3 欄或兩個元件互換位置，最小化 J = 規則問題·10⁶ + 碰撞·10⁵ + 交叉·10³ + 總線長。硬限制：一孔一物、本體不重疊、腳不插在別的元件底下、同一導通群組裡只能有同一個網路的腳。
- **L2 腳位重新分配**：訊號網路接開發板的哪隻腳，只要功能相同（ADC／PWM／一般 GPIO）就可互換；以動態規劃找「腳位左右順序＝元件左右順序」的單調配對。序列埠、I2C、SPI 腳不動。韌體腳位對照同步更新。
- 兩者有改動時，設計紀錄要寫明（誠實揭露）。

## 6. 對元件擺放的要求（給 AI 設計端）

接線要成功，擺放必須留空間：

- 每個需要接線的腳，它的導通群組至少要有 1 個空孔（不被元件本體蓋住）。
- 元件依它接的開發板腳位順序由左到右排，可以大幅減少交叉。
- 元件本體不能重疊（`detectPartOverlaps`），腳不能插在別的元件底下。
- 6mm 按鈕跨中央溝（腳 1/2 在同一欄 E/F）。

## 7. 支援的麵包板

規範只讀孔位資料，任何 `BreadboardSpec` 都適用。內建：

| 規格 | 主區 | 電源軌 |
|---|---|---|
| `breadboard_830` | 63 欄 × A–J | 上下各 + / −，每條 50 孔，中間斷開（2 段） |
| `breadboard_400` | 30 欄 × A–J | 上下各 + / −，每條 25 孔，整條導通 |
| `breadboard_170` | 17 欄 × A–J | 無 |

## 8. 驗證（測試）

- `test/autowire.test.ts`：拿掉內建範例的導線，依規範重新產生，必須全部通過 R1–R6。
- `test/autowire.fuzz.test.ts`：在 830／400／170 三種板子上隨機擺放電阻、LED、按鈕、DHT22，隨機配電源／地／訊號網路，每一個都要通過 R1–R6；俯視交叉另外統計。
